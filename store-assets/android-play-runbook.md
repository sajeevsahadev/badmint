# Badminton 360 — Google Play release runbook (TWA via PWABuilder)

The Android app is the badminton360.app PWA wrapped as a Trusted Web Activity,
generated by **PWABuilder**. Play App Signing is enabled (Google holds the app
signing key; you upload with your **upload key**).

## Fixed facts — never change these
- **Package ID:** `app.badminton360.twa`
- **Live site:** https://badminton360.app  (start_url `/`, scope `/`, standalone, portrait)
- **Digital Asset Links:** `public/.well-known/assetlinks.json` (served via `vercel.json`).
  Holds TWO sha256 fingerprints: the **upload key** and the **Play app-signing key**.
  Do not edit unless the package ID or a signing key changes.
- **Signing:** reuse `signing.keystore` + the alias/passwords in `signing-key-info.txt`
  from the release folder. **Losing this keystore = you can never update the app.** Back it up.

## Per-release steps

### 1. (Optional) manifest / icon / name changes
- Edit `vite.config.js` (the `manifest` block) → `git push` → wait for Vercel deploy.
- PWABuilder reads the LIVE manifest. The "Download Manifest" button in PWABuilder does
  NOT update the app — ignore it.
- Skip this step entirely for a routine "fix target API level" release.

### 2. Regenerate the Android bundle (this is what bumps the target API level)
1. https://www.pwabuilder.com → enter `https://badminton360.app` → Start.
2. **Package For Stores → Android → Google Play**.
3. In the options dialog:
   - **Package ID:** `app.badminton360.twa` (must match exactly).
   - **App name:** Badminton 360
   - **Version (versionName):** bump, e.g. `1.0.1`
   - **Version code:** must be **higher than the last uploaded** (check Play Console →
     previous release). If unsure, use a safely higher integer.
   - **Signing key:** choose **"Use existing / Import"**, upload `signing.keystore`,
     and enter key alias + key password + keystore password from `signing-key-info.txt`.
     (Do NOT let it generate a new key.)
   - Leave the target API at PWABuilder's current default — that's what clears the warning.
4. **Download** → you get a `.aab` (App Bundle) signed with your upload key.
   Keep the old bundles; upload only the NEW `.aab`.

### 3. Upload to Play Console
1. Play Console → Badminton 360 → **Test and release → Testing → Closed testing** (or
   Production when ready) → **Create new release**.
2. Drag the new `.aab` into **Upload app bundles**.
3. Confirm: version code is higher than previous, and the shown **target API level** is the
   new (higher) value — the warning banner should not apply to this bundle.
4. Add release notes → **Save → Review release → Start rollout**.

### 4. Verify
- Once the bundle is processed, the app-level "target API level" warning clears for the
  new release.
- Install from the test track and confirm the app opens **full-screen with no browser
  address bar** — if a URL bar shows, `assetlinks.json` / the signing fingerprint is wrong.

## Notes
- versionName (e.g. 1.0.1) is cosmetic; **versionCode (integer)** is what Play enforces
  for "must be higher than previous".
- The web app version in `package.json` is independent of the Android versionCode.
